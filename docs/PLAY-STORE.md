# 구글 플레이 등록 — meogja 용 정리 (2026-09-04)

BLOCKPOP(`~/dev/tmp/demo_1`)을 실제로 등록하면서 밟은 절차와 지뢰를 meogja 기준으로 옮겼다.
**추측이 아니라 그날 실제로 화면을 보며 한 것들**이고, 틀렸던 것도 같이 적는다 — 같은 곳에서
두 번 헤매지 않으려는 문서다.

---

## 0. 먼저 알아야 할 것 — 이 프로젝트는 웹앱이다

meogja 는 Next.js 웹앱이고 Vercel 에 떠 있다. 안드로이드 프로젝트가 없다.
그래서 BLOCKPOP 과 **출발점이 다르다.**

| | BLOCKPOP | meogja |
| --- | --- | --- |
| 정체 | Capacitor 로 감싼 게임 | Next.js 웹앱 |
| 안드로이드 프로젝트 | 있음 | **없다 — 만들어야 한다** |
| 감싸는 방법 | Capacitor | **TWA** (아래 2장) |

다행히 **PWA 요건은 이미 갖췄다**:
`public/manifest.json` 이 `display: standalone`, 아이콘 192·512(maskable 포함), `start_url`,
`theme_color` 를 갖고 있고, `src/app/layout.tsx` 가 `sw.js` 를 등록한다.
TWA 가 요구하는 것이 정확히 이것들이라 **추가 작업이 거의 없다.**

`src/app/profile/page.tsx:1374` 회원 탈퇴 버튼 → `DELETE /api/auth/delete-account`.

필요하고 `/privacy` 의 "3. 보관 기간" 한 줄로는 요건 셋을 다 못 채운다.
→ **`/delete-account` 공개 페이지 하나가 아직 필요하다.**

## 2. meogja 를 앱으로 만드는 법 — TWA

TWA(Trusted Web Activity)는 크롬 엔진으로 웹사이트를 **주소창 없이** 띄우는 안드로이드 앱이다.
구글이 공식 지원하는 방식이라 단순 웹뷰 래퍼보다 정책상 안전하다.

### 2-1. 만들기

> ⚠️ **이 머신에는 java 도 Android SDK 도 없다 (2026-09-05 확인).**
> `bubblewrap` 은 JDK 17 + Android SDK 를 깔아야 돈다. 설치가 부담이면 아래 ② PWABuilder
> (브라우저에서 AAB 를 받아온다)가 실질적으로 유일한 길이다.

두 가지 길이 있다. 어느 쪽이든 결과는 같다.

```bash
# ① Bubblewrap (구글 공식 CLI)
npm i -g @bubblewrap/cli
bubblewrap init --manifest https://meogja.vercel.app/manifest.json
bubblewrap build      # → app-release-signed.aab / .apk
```

② PWABuilder(pwabuilder.com)에 주소를 넣으면 웹에서 같은 것을 만들어 준다. CLI 가 부담스러우면 이쪽.

`bubblewrap init` 이 물어보는 것들:
- **패키지 이름** — `com.dalgonacrunch.meogja`
- **서명 키** — 새로 만들거나 기존 것을 쓴다.
  ⚠️ 이 키를 잃으면 **같은 앱으로 업데이트를 영원히 못 한다.** 백업해 둘 것
- 앱 이름·테마색 등은 `manifest.json` 에서 자동으로 읽는다

### 2-2. assetlinks.json — 이걸 안 하면 주소창이 남는다

TWA 는 "이 앱이 이 사이트의 주인이 맞다"를 증명해야 주소창을 숨긴다.
증명 파일을 **사이트 쪽에** 올린다.

```
public/.well-known/assetlinks.json
```

내용은 `bubblewrap` 이 만들어 준다(`assetlinks.json` 생성 명령). 서명 키의 SHA-256 지문이 들어간다.

> **Play 앱 서명을 쓰면 지문이 바뀐다.** 업로드 키가 아니라 **구글이 발급한 앱 서명 키**의
> SHA-256 을 넣어야 한다. Play Console → 테스트 및 배포 → 앱 무결성 → 앱 서명에서 받는다.
> 이건 **AAB 를 한 번 올려야** 생기므로, 순서가 이렇게 된다:
> AAB 업로드 → 앱 서명 키 지문 확보 → assetlinks.json 갱신 → Vercel 배포 → 앱에서 확인.

Vercel 은 `public/` 을 그대로 서빙하므로 파일만 두면 된다.
확인: `https://meogja.vercel.app/.well-known/assetlinks.json` 이 200 이면 됨.

### 2-3. 정책 위험 — 이건 진지하게 보라

구글은 **"최소 기능" 앱**을 반려한다. 웹사이트를 그냥 감싸기만 한 앱이 대표 사례다.
TWA 자체는 합법이지만, 심사자가 "이건 그냥 웹사이트인데?"라고 판단하면 걸린다.

방어가 되는 것들:
- 오프라인에서도 뭔가 보여줄 것 (service worker 가 이미 있다 — 캐시 전략을 확인해 둘 것)
- 앱다운 진입 경험 (스플래시, standalone 표시 — manifest 에 이미 있다)
- 푸시 알림처럼 **웹에 없던 값**이 하나라도 있으면 훨씬 안전하다

meogja 는 "모임 만들고 링크 공유 → 투표 → 결과"가 핵심이라, **투표 마감·결과 알림 푸시**가
붙으면 앱으로 존재할 이유가 분명해진다. 심사 방어와 제품 가치가 같은 방향인 드문 경우다.

## 4. 오늘 실제로 밟은 지뢰 — 반복 금지

### ① 개발자 인증에 패키지 이름을 미리 등록하지 마라 ★ 가장 비쌌다

Play Console 의 **Android 개발자 인증** 화면에서 패키지 이름을 수동 등록했더니, 그 이름이
**영구히 잠겼다.** 그 뒤로 앱 만들기에서 같은 이름이 "이미 사용 중"으로 거부됐다.
등록을 지워도 풀리지 않았다 — 구글은 한 번 등록된 패키지 이름을 회수해 주지 않는다.

결과: `com.blockpop.puzzle` 을 버리고 `com.dalgonacrunch.blockpop` 으로 갈아탔다.

**그 화면은 Play 밖에서 배포하는 앱용이다.** Play 로만 배포할 앱은
**앱 만들기 시점에 자동 등록**된다. 손대지 마라.

### ② 사용자끼리 글이 오가면 신고·차단이 필요하다

채팅이나 공개 닉네임이 있으면 구글 UGC 정책이 **신고 기능·차단 기능·모더레이션**을 요구한다.
BLOCKPOP 은 대기실 자유 채팅이 있었는데 셋 다 없어서, 출시 직전에 **정해진 문구 고르기(퀵챗)로
바꿨다.** 사용자가 글을 만들지 않으면 UGC 가 아니다.

meogja 는 **모임 이름·닉네임·메뉴 직접 입력**이 UGC 에 해당할 수 있다. 확인해 둘 것.
자유 입력을 남길 거면 신고 창구(최소한 메일 링크)라도 있어야 한다.

### ③ 스토어 설명에 관리자 전용 기능을 적지 마라

`modes.js` 에 모드가 여러 개 정의돼 있길래 "사용자가 고를 수 있다"고 설명에 적었는데,
그 손잡이들은 **관리자 모드에서만 보이는** 것이었다. 설명과 앱이 다르면 반려된다.

**정의가 있다고 노출되는 것이 아니다.** 노출 지점(UI)까지 확인하고 적을 것.

### ④ 실기기 스크린샷에는 테스트 광고가 찍힌다

광고가 있는 앱이면 실기기 캡처에 "테스트 광고" 배너가 그대로 들어간다.
웹 빌드를 Playwright 로 찍으면 광고가 아예 없다. meogja 는 광고가 없으니 해당 없지만,
**해상도**는 챙길 것 — 기존 캡처가 450×840 이라 다시 뽑았다.

### ⑤ 검사 도구는 번들을 먼저 다시 만들어야 한다

`e2e:build` 를 건너뛰고 검사를 돌려 **옛 번들**을 검사하고 "안 고쳐졌다"고 오판했다.
meogja 도 `next build` 후에 검사할 것.

### ⑥ 내가 틀렸던 것 — 참고

- "패키지가 바뀌면 구글 로그인이 깨진다" → **틀렸다.** BLOCKPOP 은 Supabase 브라우저 흐름이라
  안드로이드 OAuth 클라이언트가 경로에 없었다. 어떤 흐름인지 **코드를 따라가 보고** 판단할 것
- "앱 만들기 화면은 패키지 이름을 안 묻는다" → 예전엔 그랬지만 지금은 묻는다
