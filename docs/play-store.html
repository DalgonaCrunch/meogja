구글 플레이에 meogja 올리기

BLOCKPOP 을 실제로 등록하면서 밟은 순서와, 그때 빠진 함정들. 추측이 아니라 그날 화면을 보며 한 것들이다.

meogja 는 출발점이 다르다. Next.js 웹앱이라 안드로이드 프로젝트가 아예 없다. 대신 manifest.json 이 standalone + 아이콘 192·512(maskable) 을 갖췄고 sw.js 도 등록돼 있다 — TWA 가 요구하는 것이 정확히 그것들이라 감싸는 일은 짧다.

먼저 확인할 것 — 12명 규칙

2023-11-13 이전 개인면제 (소급 적용 없음)
법인 · 조직면제 — 대신 D-U-N-S 번호와 사업자 서류

앱 종류와 무관하다. 게임이든 유틸이든 계정에 걸린다. BLOCKPOP 으로 한 번 통과하면 meogja 때도 필요한지 알 수 있다 — 계정 단위인지 앱 단위인지는 구글 문서에 안 적혀 있다.

순서

앞 단계를 건너뛰면 뒤가 안 열린다

  1. 개인정보처리방침 페이지 만들기
    없으면 어느 단계도 못 넘어간다. 별도 저장소 + GitHub Pages 가 편하다. 계정 기능이 있으면 계정 삭제 요청 페이지도 따로 필요하다 — 방침 안의 한 줄로는 부족하다.
  2. TWA 로 감싸기 + 서명 키
    bubblewrap init --manifest https://meogja.vercel.app/manifest.json → bubblewrap build. 패키지는 com.dalgonacrunch.meogja.
    서명 키를 잃으면 같은 앱으로 업데이트를 영원히 못 한다. 만들자마자 백업.
  3. Play Console 앱 만들기
    앱 이름 · 기본 언어 · 앱/게임 · 무료/유료 · 패키지 이름. 패키지 이름은 여기서 처음 넣는다.
  4. 앱 콘텐츠 선언 9종
    개인정보처리방침 · 로그인 세부정보 · 광고 · 콘텐츠 등급 · 타겟층 · 데이터 보안 · 정부 앱 · 금융 기능 · 건강. 전부 채워야 테스트 트랙이 열린다.
    데이터 보안은 스토어에 공개된다. supabase-schema.sql 을 보고 실제 저장 항목대로 채울 것.
  5. AAB 업로드 → 앱 서명 키 지문 확보
    여기서 순서가 꼬인다. assetlinks.json 에 넣을 지문은 업로드 키가 아니라 구글이 발급한 앱 서명 키의 SHA-256 인데, 그건 AAB 를 한 번 올려야 생긴다.
  6. assetlinks.json 배포
    public/.well-known/assetlinks.json 에 두면 Vercel 이 그대로 서빙한다. 이게 있어야 앱에서 주소창이 사라진다.
    확인: meogja.vercel.app/.well-known/assetlinks.json 이 200
  7. 스토어 등록정보
    아이콘 512 · 그래픽 1024×500 · 스크린샷 1080×1920 2~8장 · 간단한 설명 80자 · 자세한 설명 4000자.
  8. 테스터 등록 → 14일 → 프로덕션 신청
    지메일이 아니어도 된다. 구글 계정으로 등록된 주소면 통과한다. Workspace 회사 메일도, 구글 그룹스도 된다.

밟은 지뢰

BLOCKPOP 에서 실제로 당한 것들. 순서는 비용순

비용 — 패키지 이름을 통째로 버렸다

개발자 인증 화면에서 패키지 이름을 미리 등록했다

Play Console 의 Android 개발자 인증에서 com.blockpop.puzzle 을 수동 등록했더니 그 이름이 영구히 잠겼다. 앱 만들기에서 "이미 사용 중"으로 거부됐고, 등록을 지워도 풀리지 않았다. 구글은 한 번 등록된 패키지 이름을 회수해 주지 않는다.

그 화면은 Play 밖에서 배포하는 앱용이다. Play 로만 배포할 앱은 앱 만들기 시점에 자동 등록된다. 손대지 마라.
비용 — 출시 직전 기능 하나를 갈아엎었다

사용자끼리 글이 오가면 신고·차단이 필요하다

채팅이나 공개 닉네임이 있으면 UGC 정책이 신고 · 차단 · 모더레이션 셋을 요구한다. BLOCKPOP 은 대기실 자유 채팅이 있었는데 셋 다 없어서, 정해진 문구 고르기로 바꿨다. 사용자가 글을 만들지 않으면 UGC 가 아니다.

meogja 는 모임 이름 · 닉네임 · 메뉴 직접 입력이 여기 해당할 수 있다. 자유 입력을 남길 거면 신고 창구(최소한 메일 링크)라도 두자.
비용 — 반려됐으면 며칠

스토어 설명에 관리자 전용 기능을 적었다

modes.js 에 모드가 여러 개 정의돼 있길래 사용자가 고를 수 있다고 적었는데, 그 손잡이들은 관리자 모드에서만 보이는 것이었다. 설명과 앱이 다르면 반려된다.

정의가 있다고 노출되는 것이 아니다. 노출 지점(UI)까지 확인하고 적을 것.
비용 — 스크린샷 전부 다시

실기기 캡처에 테스트 광고가 찍혔다

광고가 있는 앱은 실기기 캡처에 "테스트 광고" 배너가 그대로 들어간다. 해상도도 450×840 으로 낮았다.

웹 빌드를 Playwright 로 1080×1920 캡처하면 광고가 아예 없다. meogja 는 광고가 없지만 해상도는 챙길 것.
비용 — 잘못된 진단으로 한 바퀴

번들을 다시 만들지 않고 검사했다

빌드를 건너뛰고 E2E 를 돌려 옛 번들을 검사해 놓고 "안 고쳐졌다"고 판단했다.

meogja 도 next build 뒤에 검사할 것.

TWA 특유의 정책 위험

이건 진지하게 볼 것

구글은 "최소 기능" 앱을 반려한다. 웹사이트를 그냥 감싸기만 한 앱이 대표 사례다. TWA 자체는 합법이지만 심사자가 "이건 그냥 웹사이트인데?" 라고 보면 걸린다.

  • 오프라인에서도 뭔가 보여줄 것 — service worker 캐시 전략 확인
  • 앱다운 진입 — 스플래시 · standalone (manifest 에 이미 있다)
  • 웹에 없던 값이 하나라도 있으면 훨씬 안전하다
meogja 는 "모임 만들고 링크 공유 → 투표 → 결과"가 핵심이라, 투표 마감·결과 알림 푸시가 붙으면 앱으로 존재할 이유가 분명해진다. 심사 방어와 제품 가치가 같은 방향인 드문 경우다.
